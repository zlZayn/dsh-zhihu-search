# 决策：在工具描述里声明「结果不含图片」（2026-09-13）

已实施。

## 问题

- 知乎图文并茂的文章很常见，但模型从搜索结果里拿不到任何图片，描述里也没说。
- 实测（3 个查询、30 条结果）：单条结果 16 个字段，唯二带图的是 `AuthorAvatar` 与 `AuthorBadge`（作者头像与徽章），跟正文无关；`ContentText` 既无 `<img>`、无 Markdown 图片语法、也无 URL。
- 最直接的证据：一篇摄影教程的摘要开头是「不废话先放图：」，后面直接接下一段文字 —— 图在上游的摘要接口就被剥掉了。
- 描述不写这一点，模型会向用户承诺「我看看这张图」，而它永远看不到。

## 决策

- 两个搜索工具的描述末尾各加一句：只返回文字摘要与原始链接，结果不含图片。
- 写「与原始链接」而不是只写「文字摘要」：链接是这两个工具的核心价值，不能被这句话说没了。

## 替代方案

- **不写**：模型继续对图文内容做超出能力的承诺，用户按承诺提要求后才发现拿不到。
- **写成「无法访问图片」**：听起来像暂时故障，实际是接口形态，永远如此。
- **在 render 里逐条标注「本结果无图」**：每条多一行噪声，而这是结果的固有属性，不是单条差异。
- **给模型留一条取图路径**（例如把 `AuthorAvatar` 或原文 HTML 里的图片交给 `read_image`）：上游根本没给正文图片 URL，`web_fetch` 也只回文本，无中生有做不到。

## 影响

- 描述多一句，每步上下文多约 15 字，换来模型不再承诺它给不出的东西。
- [test/tool.test.ts](../../test/tool.test.ts) 固化这条声明：两个搜索工具的描述都必须含「不含图片」，删掉即红。
- 直答不加：它返回生成式文本，同样没有图，但形态不同，等真出现误承诺再加。
