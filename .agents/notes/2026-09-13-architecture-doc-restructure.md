# 决策：架构文档补齐缺失契约，目录规则改为引用而非复述（2026-09-13）

已实施。

## 问题

- 架构文档 102 行，工具描述约定被夹在两组契约之间；防错清单混了上游行为、本实现与契约纪律三类问题。
- 文档里没有结构视图：依赖方向与「哪些模块不认识框架」只散落在各目录 README。
- **错误契约与缓存／限流完全没有落点**——它们是跨模块契约，却只在代码注释与目录规则里各写半句。
- 各目录 `AGENTS.md` 的规则与架构文档的表述长期各存一份，改一处漏一处。

## 决策

- 架构文档重排为 12 节：核心目标 / 不可破坏的约束 / **模块骨架与依赖方向**（新） / 请求生命周期（仅搜索路径） / 端点契约 / **错误契约**（新） / **缓存与限流**（新） / 密钥解析契约 / 两半体约束 / 工具描述约定 / 防错清单（按三类分小节） / 与知乎官方文档的偏差。
- 每个偏差表条目**注明测的是哪个端点**——两个端点行为并不一致，不注明就会被当成通用结论。
- 目录 `AGENTS.md` 的每条规则末尾注明它派生自架构文档的哪一节；规则正文不再复述理由。
- 子 README 的导出清单与架构引用同步对齐源码，正文只留规则与指针。

## 替代方案

- **规则正文写全理由**：每处都要跟着架构改动同步，实际结果是两边都过时——就是要修的现状。
- **只留架构文档一条指针，删掉目录规则**：规则层是自动注入的，删掉后 Agent 在子目录工作时看不到约束。
- **把错误契约与缓存限流写进子 README**：违反「一个事实一个 home」，且这两节描述的是跨模块契约，不属于任何单个目录。
- **把额度数字（5000/天）写进架构文档**：额度随账号与实名状态变化（实测未实名时 10/天），写死会误导；改为指向探测笔记。

## 影响

- 改架构节标题即破坏所有目录规则的引用。链接校验只覆盖 URL，**覆盖不到这种散文引用**（「错误契约」不是 fragment），因此靠人工保持；新增节时按同一风格补引用。
- 目录规则与架构文档现在是「规则 → 理由」的单向关系：改理由不必动规则，改规则必须回头确认理由仍成立。
