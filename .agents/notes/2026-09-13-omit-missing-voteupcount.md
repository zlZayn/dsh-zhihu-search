# 决策：上游没报点赞数时省略字段，渲染层整段省略（2026-09-13）

已实施。

## 问题

- 全网搜索会返回第三方网页，实测它们既没有 `ContentType` 也没有 `VoteUpCount`。
- 投影层把缺失的 `VoteUpCount` 兜底成 `0`，渲染层无条件输出 `**点赞**: 0` —— 等于给外站广告页标上「没人赞」。
- 同一类问题在 `ContentType` 上已经修过（兜底成 `Answer` / `Article` 会把广告页说成知乎回答），`VoteUpCount` 是漏掉的那一半。

## 决策

- `voteUpCount` 改为**可选字段**：上游没报就整个键省略，`0` 只表示真的零赞。
- 输出 schema 去掉该字段的 `required: true`，两个搜索工具同步改，由 schema 一致性测试守护。
- 渲染层在缺失时整段省略 `**点赞**` 段，与 `**类型**` 的处理一致。

## 替代方案

- **保持 `0`**：把「不知道」显示成「没人赞」，会让模型据此贬低一个它并不了解的来源。
- **渲染成 `**点赞**: 未知`**：多一种取值就多一种解释成本，且把非数值噪声写进模型上下文。
- **加一个 `voteUpCountKnown: boolean`**：多一个字段只为了表达「前一个字段可不可信」，schema 变宽而不变清楚。
- **改成联合类型**（`oneOf: [number, null]`）：同样是 schema 改动，却让 `null` 进入 Canonical Value，回放与 UI 都要多处理一种空值。

## 影响

- **输出 schema 变更**：消费方不能再假设 `items[].voteUpCount` 一定存在。本插件自身的 render 与 presentationMeta 已同步，二者都不读该字段做结构判断。
- 站内搜索走同一条省略路径；上游目前恒报该字段，实测未见缺失。
- 数据里出现大量 `0` 赞的旧会话记录仍是合法值，回放不受影响。
