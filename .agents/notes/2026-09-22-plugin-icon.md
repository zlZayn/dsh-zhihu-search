# 插件图标：把 `assets/logo.svg` 里的**鲸鱼 + 知**烘进 36×36 的 `icon.svg`（同色双拼）

**一轮之内给包根补上 `icon.svg` 并声明它，这是它的决策记录。**
几何与配色一律是本机算出来的（解析 path 数据 + WCAG 相对亮度），不是目测。

> **一轮之内改过一次构图**：初版只取鲸鱼一支、19 × 19。用户看过四张对照图后选了
> **构图 (c) + 配色 c1**（鲸鱼 + 知两支、同填知乎蓝），本文记的是**最终那一版**；
> 变更理由与代价见下面的「为什么是两支同色」。

## 问题

宿主 0.1.7 支持插件自带图标（顶层 `"icon": "./icon.svg"`），官方两个实验包都有；
本插件此前的决策是[**不加**](2026-09-22-plugin-display-metadata.md)（仓库没有可用资产，硬造等于替维护者定视觉方向）。
本轮用户拍板**两仓都加**，并指定 zhihu 这一侧的素材与形态：

> 「`assets/logo.svg` 放在中央，**不是白底**因为要兼容亮暗模式」

## 宿主的硬约束（`packages/boot/app-boot/src/package-meta.ts` 的 `iconOf`，逐条核过）

相对路径；扩展名限 `.svg/.png/.jpg/.jpeg/.webp`；**realpath 后必须留在清单目录内**；普通文件；**≤ 256 KiB**；
返回 **base64 data URL → 按图片渲染**（所以 `currentColor`、外链图片、外部 CSS 与字体**一律不起作用**，必须自包含）。

## 素材勘查：`assets/logo.svg` 是三块，不是一块

它是 `viewBox="0 0 523 346"` 的横版**字标**（15.8 KB），三个 path 各是一种色，外接框（锚点法）实测：

| path（文件里第几条） | fill | 外接框（源坐标） | 是什么 |
|---|---|---|---|
| **#0** | `#1F5B95` 深蓝 | x 48.8–476.5，y 295.9–333.8（427.7 × 37.9，高宽比 0.089） | **底部那行 `dsh-zhihu-search` 小字** —— **丢掉** |
| **#1** | `#0084FF` 知乎蓝 | x 257.2–518.3，y 33.3–294.4（**261.1 × 261.1**） | **鲸鱼**（用户与 Lead 口径里的「path#2」）—— 保留 |
| **#2** | `black` 黑 | x 8.6–358.8，y 10.9–291.7（350.2 × 280.8） | **「知」方标**（口径里的「path#1」）—— 保留 |
| 两支合并 | — | 509.7 × 283.5（长宽比 **1.798**） | 这就是构图 (c) 的内容 |

> **命名对齐（免得下一个人数错）**：Lead/用户的口径是**从 0 数**的，
> 「path#0 = 那行字、path#1 = 知方标、path#2 = 鲸鱼」；本表第一列是**文件里第几条**，也跟着从 0 数，
> 所以：他们的 #1 是本表的 `#2`，他们的 #2 是本表的 `#1`。**丢掉的是最扁的那条**（高宽比 0.089，
> 与另外两条差一个数量级）—— 判据是几何，不是猜名字。

## 决策

### 取哪两支：鲸鱼 + 知，丢掉底部那行小字

- **丢掉 #0（`dsh-zhihu-search` 那行）**：它是全篇最扁的一条（高宽比 0.089），
  36 单位下每个字母只有 ~0.6 单位高 —— 渲染出来是一道虚线。用户也明确点名不要它。
- **留下 #1（鲸鱼）与 #2（知）**：鲸鱼是作者自己的标记（261 × 261 的正方形，作者把它取作「鲸鱼」），
  「知」是知乎的品牌字；两者合起来才是「本插件用的知乎」。
- 初版只取鲸鱼一支（19 × 19）。用户看对照图后改成两支同色版，代价见下一节。

### **为什么是两支同色**（用户的选择，记成有意的取舍）

用户从四张对照图里选了 **构图 (c) + 配色 c1**：两支都填 `#0084FF`。**他知道代价** ——
对照图里标过、本记录也量出来了：

- 逐高度带扫两支的边缘（锚点 ±0.5 窗口、0.25 单位步长）：
  **最窄的水平间隙只有 0.360 单位**（在 y ≈ 16.25 那一带，知 的右缘 20.078 对 鲸鱼 的左缘 20.438）；
  再往上（y 13–15.5）知的一笔在 x 上**越过了**鲸鱼的左缘（最近处相差 **−1.827 单位**），
  也就是说在那个高度带两支的投影在水平方向**已经交叠**。
- 换算成渲染尺寸：**0.36 CSS px**（卡片 36px）/ 设备像素 **0.59 px**；行内（30px）**0.30 CSS px**。
  锚点法给的是**上界**（真实曲线的间隙只会更小），所以结论是 ——
  **在卡片尺寸下这两支确实会连成一块**，与用户的预期一致，不是我们没看出来。
- 为什么仍然照做：**用户看过图并指定了这个组合**；同色的收益是视觉上合成一个单一标记，
  代价是两支的边界在 36px 下不可分。这是**取舍**，不是缺陷 —— 换色（例如鲸鱼浅蓝、知深蓝）
  会把它们分开，但那不是用户选的那一版。要改就再问一次，而不是这里自作主张。

### 几何：合并外接框 **19.0 × 10.6**，左右留白 8.5，上下留白 12.7

官方配方是「36×36 画布、图形居中、四周留 8–9（图形本体约 18–20）」。两支合并后的长宽比是 **1.798**，
**等比缩放**下不可能同时让宽与高都落在 19：

| 样本 | 图形本体 | 留白 左/右/上/下 |
|---|---|---|
| `agent-team-profile/icon.svg` | 18.0 × 18.0 | 9.03 / 8.93 / 8.57 / 9.39 |
| `voice-input-bundle/icon.svg` | 20.9 × 18.5 | 7.56 / 7.56 / 8.77 / 8.77 |
| **本仓 `icon.svg`（实测回读）** | **19.000 × 10.567** | **8.500 / 8.500 / 12.716 / 12.716** |

做法：`scale = 19 / 509.740 = 0.03727427`（按**长边**定 19，即宽那一维），
平移量解到「合并外接框左上角落在 (8.5, 12.716)」——
**把变换烘进坐标**（保留 4 位小数）而不是留一个 `transform` 属性，36 画布里的数字**直接就是**它出现的位置。
如实记两点：

1. **图形本体只有 10.57 高**，所以上下留白到了 12.7，**超出官方那 8–9 的区间** ——
   这是两支合并后 1.798 的长宽比带来的，不是缩放算错。要把它填满就得裁内容或拉伸，两者都不做。
2. 因此**鲸鱼本身在这一版里只有 9.73 × 9.73 CSS px**（上一版独占 19 × 19）—— **缩到上一版的 51.2%**。
   可读性随之下降，见下面的「可读性」一节。

回读校验：两支的外接框分别 `17.767..27.500 × 13.550..23.284`（鲸鱼）与 `8.500..21.554 × 12.716..23.184`（知），
命令序列与源 path **逐段一致**（`MCC…L…Z` 逐字相同），数字个数 **182 : 182** 与 **434 : 434** 完全对齐，
逆变换回源坐标的最大误差 **0.000678**（四舍五入造成，形状未变）。

### 配色：沿用 logo 自己的 `#0084FF`，**不改色**

「亮暗都要能看」是判据，所以量化过（WCAG 相对亮度，两种主题的卡片底色都取 `--dsw-alias-bg-layer-3`：
亮 `#FFFFFF`、暗 `#2B2B2C`）：

| 候选 | 亮底 | 暗底 | 取小 |
|---|---|---|---|
| **`#0084FF`（logo 原色，本仓采用）** | **3.66** | **3.87** | **3.66** |
| `#1E80FF` | 3.76 | 3.76 | 3.76 |
| `#3B82F6` | 3.68 | 3.85 | 3.68 |
| `#7AAAFF`（官方 icon 用的亮蓝） | 2.33 | 6.08 | 2.33 ✗ |
| `#145AF3`（官方深蓝） | 5.55 | 2.55 | 2.55 ✗ |
| `#2563EB` | 5.17 | 2.74 | 2.74 ✗ |

- `#0084FF` 在两种底色上都过 WCAG 1.4.11「非文本对比」的 **3:1** 下限，且**两边的值几乎对称**（3.66 / 3.87）——
  这正是「亮暗都要能看」想要的性质；官方那两个蓝都是**一边过一边不过**（2.33 / 2.55）。
- 它是**素材自带的颜色**（`assets/logo.svg` 里鲸鱼那支的 `fill`），不是新调的品牌色 —— 不用维护者再拍一次板。
  **这一版把「知」那支原本的 `black` 也改成它**（用户选的 c1）：不改的话黑字在深色主题上直接消失，
  而且两色不同会让同一枚图标看起来是两个东西。
- **不加底板**（用户明确要求「不是白底」）：图标是透明底 + 两支同色的图形。
  副作用如实说：**知乎蓝在深色底上偏暗**（3.87 是过线，不是醒目）；要更亮就得上 `#7AAAFF` 那种，
  代价是亮色底掉到 2.33。这一条是取舍，摆在这里备查。

### 去掉投影

源文件那层 `<g filter="...">` 是 `stdDeviation=5` 的白色投影。缩到 36 单位后模糊半径只剩
`5 × 0.0373 = 0.19` 单位、偏移 `0.15/0.07` 单位 —— 在 36 px 的渲染尺寸下远不到半个像素，
**只会让边缘发灰**；而且投影是白色的，在亮色主题上本来也看不见。所以**整层 `<g>` 与 `<defs>` 都没要**。

### 可读性（如实说，不美化）

宿主那一格的实际尺寸：卡片 `CARD_ARTWORK_SIZE = 36`（48px 框里画 36px）、
行内 `ROW_ARTWORK_SIZE = 30`（40px 框里画 30px），`PackageArtwork` 就是 `<img width=size>` —— 1 单位 = 1 CSS px。

| 量 | 36 画布 | 卡片（36 CSS px） | 行内（30 CSS px） |
|---|---|---|---|
| 合并外接框 | 19.000 × 10.567 | 19.0 × 10.6 | 15.8 × 8.8 |
| 鲸鱼 | 9.733 × 9.733 | **9.7 × 9.7**（设备像素 16.1 × 16.1） | 8.1 × 8.1 |
| 知 | 13.054 × 10.468 | 13.1 × 10.5（设备像素 21.5 × 17.3） | 10.9 × 8.7 |
| 两支最窄水平间隙 | 0.360 | **0.36**（设备像素 0.59） | 0.30 |
| 知的笔画粗细（最窄一笔） | ≈ 1.0–1.2 | ≈ 1.0–1.2 CSS px ≈ **1.7–2 设备像素** | ≈ 0.9 |

- **这一版比上一版小一半**：鲸鱼从 19 × 19 掉到 9.7 × 9.7（51.2%）。
  9.7 px 的方标在桌面上**勉强能认**，但已经进入「看得出有个图形、看不清细节」的档。
- **两支在卡片尺寸下连成一块**（最窄间隙 0.36 CSS px，见上一节）—— 与用户预期一致。
- 结论一句话：**这枚图标在 36px 下是「一块蓝色双拼剪影」，不是两个可分辨的图形**。
  这是用户选定的形态；要恢复辨识度得回到单支构图（上一版）或给两支分色。

### 自包含

**两个 `<path>`**（鲸鱼 + 知）、无 `transform`、无 `filter`、无 `defs`、无 `href` / `url(` / `@import` / `<image` / `<style` / `font-family`；
`fill="#0084FF"` 写死不用 `currentColor`（data URL 渲染时它取不到值）。文件 **5003 B**（上限 262144 B）。

## 随包与断言

- `package.json` 顶层 `"icon": "./icon.svg"`，`files` 收录 `icon.svg`。
- **那条「将来声明 icon 时它也要进包」的断言现在真的生效了**：[scripts/plugin-metadata.mjs](../../scripts/plugin-metadata.mjs)
  在原本只判「路径是否越界」的基础上补了四条 —— 文件在、扩展名在宿主名单内、`files` 收录、≤ 256 KiB。
  与展示元数据同一份判定，`npm run check:release` 与 [test/plugin-metadata.test.ts](../../test/plugin-metadata.test.ts) 都读它。
- **防空转（端到端实跑）**：临时把 `"icon.svg"` 从 `files` 里摘掉 → `check:release` **退出码 1**，
  报 `files 收录 icon.svg —— 没随包的图标在 npm 上不存在…`；还原后 `release check passed`（退出码 0）。
  `npm pack --dry-run` 的产物清单里也有 `icon.svg`（1.6 kB）。

## 影响

- **对使用者**：插件页的 bundle 卡片、详情页与设置里的插件清单开始显示这枚图标（此前是面板默认图案）。
  没有它时宿主只留一条诊断、图标位空着 —— 不报错，所以这条链同样由上面的守卫兜住。
- **对截图**：图标**改变卡片外观**，所以重拍卡片图从「更新版本号与文案」升级为**必拍**；
  判废项已写进 [assets/AGENTS.md](../../assets/AGENTS.md) 与 [assets/README.md](../../assets/README.md)。
- **对素材**：`assets/logo.svg` 从「未引用」变成「被 `icon.svg` 派生引用」——
  两者**不是同一份东西**（一个是 523×346 字标、一个是 36×36 图标），
  改 logo 不自动改图标，改图标也不必动 logo。
- **回滚**：删 `icon.svg`、删清单里的 `icon` 与 `files` 那一行。没有别的耦合。
